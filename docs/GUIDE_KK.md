# Зертханалық жұмыс 1 бойынша қазақша нұсқаулық

Бұл жұмыста қоймадағы тауарларды есепке алатын ақпараттық жүйенің негізі жасалады. Нәтижесі — үш байланысты кестенің ER-диаграммасы, Python ортасы, API және интерфейс құрылымы, Git арқылы сақталатын жоба.

## 1 Жобаның мақсаты

Қойма қызметкері тауардың атауын, бағасын, санын, санатын және жеткізушісін көреді. Мысалы, «Дәптер» тауарын «Кеңсе тауарлары» санатына енгізіп, «Almaty Supply» жеткізушісіне байланыстырады. Қызметкер тауар қосады; жүйе жалпы сан мен жалпы құнды есептейді.

Бұл лабораторияның мақсаты — толық коммерциялық жүйе құру емес, жобаның архитектурасын түсіну, бастапқы құрылымын жасау және өзгерістерді Git-пен сақтау.

## 2 Кестелер мен байланыстар

| Кесте | Өрістер | Не үшін қажет |
|---|---|---|
| Category | id, name | Тауарларды санаттарға бөлу |
| Supplier | id, name, phone | Жеткізушіні және байланыс нөмірін сақтау |
| Product | id, name, price_tiyn, quantity, category_id, supplier_id | Тауардың негізгі мәліметтерін сақтау |

**PK — primary key, бастапқы кілт.** Әр жолды бірегей анықтайды. Екі тауардың атауы бірдей болса да, `id` мәндері бөлек болады.

**FK — foreign key, сыртқы кілт.** Басқа кестенің жолына сілтейді. `Product.category_id = 1` болса, ол `Category.id = 1` санатына тиесілі.

**Бірден көпке байланыс.** Бір санатта бірнеше тауар болуы мүмкін, бірақ осы модельдегі бір тауар бір санатқа ғана тиесілі. Бір жеткізуші бірнеше тауар жеткізе алады. Санат пен жеткізушіде әзірге тауар болмауы да мүмкін, сондықтан сызбада `1 : 0..N` көрсетілген.

Санат атауын әр тауарда қайта жазудың орнына, санат кестесінде бір рет сақтап, оған ID арқылы сілтейміз. Бұл мәлімет қайталануын азайтады.

`price_tiyn` — тиынмен берілген бүтін баға. 350 теңге дерекқорда 35000 болып сақталады. Интерфейс оны қайта теңгемен көрсетеді. `quantity` — тауар саны.

`docs/er-diagram.drawio` файлын draw.io сайтында ашып, қажет болса **File → Export as → PNG** арқылы экспорттаңыз. Дайын PNG файл README ішіне енгізілген.

## 3 Бағдарлама қалай жұмыс істейді

1. Пайдаланушы Streamlit формасына тауар мәліметтерін енгізеді.
2. `frontend/app.py` FastAPI серверіне POST сұранысын жібереді.
3. `app/api/routes.py` сұранысты қабылдайды.
4. `ProductCreate` схемасы баға мен санның теріс емес екенін тексереді. Маршрут санат пен жеткізушінің бар екенін тексереді.
5. SQLModel тауарды SQLite дерекқорына жазады.
6. API жасалған тауарды JSON түрінде қайтарады. Интерфейс тізімді жаңартады.

**GET** мәлімет оқиды. **POST** жаңа мәлімет қосады. **API** — интерфейс пен сервердің өзара сөйлесу ережелері. **JSON** — мәлімет алмасудың мәтіндік пішімі.

## 4 Файлдардың міндеті

| Файл немесе папка | Қарапайым түсіндірме |
|---|---|
| app/main.py | Сервердің кіру нүктесі. Қолданба мен маршруттарды қосады, іске қосылғанда кестелерді жасайды. |
| app/models/inventory.py | Python кластарымен кестелерді және енгізу схемаларын анықтайды. |
| app/db/session.py | Дерекқормен қосылым жасайды. Әр сұранысқа сессия береді. |
| app/api/routes.py | Қандай URL қандай функцияны орындайтынын анықтайды. |
| frontend/app.py | Пайдаланушы көретін бет, формалар және кестелер. |
| __init__.py | Папканы Python пакеті ретінде ұйымдастырады. |
| requirements.txt | Қажет кітапханалар мен олардың рұқсат етілген нұсқалары. |
| requirements-lock.txt | Осы ортада тексерілген нақты кітапхана нұсқалары. |
| venv/ | Осы жобаға арналған Python және кітапханалар. Git-ке жіберілмейді. |
| .gitignore | Git қадағаламауы тиіс файлдар тізімі. |
| README.md | Репозиторийді ашқан адам оқитын негізгі сипаттама. |
| tests/test_api.py | Дұрыс тауар қосылатынын және қате деректер қабылданбайтынын тексереді. |

**FastAPI** сервер мен API үшін, **Uvicorn** серверді іске қосу үшін, **SQLModel** дерекқор моделін сипаттау үшін, **Streamlit** интерфейс үшін, **requests** интерфейстен API-ге сұраныс жіберу үшін қажет.

## 5 VS Code және ИИ ассистенті

1. VS Code ашып, **File → Open Folder** арқылы жоба папкасын таңдаңыз.
2. Осы компьютерде Microsoft Python орнатылған және GitHub Copilot 0.72.0 VS Code құрамында бар. Copilot чатын ашып, өз GitHub аккаунтыңызбен кіріңіз. Басқа компьютерде **Extensions** бөлімінде Microsoft Python және GitHub Copilot орнатыңыз. Немесе Cursor қолданыңыз.
3. `Ctrl+Shift+P` → **Python: Select Interpreter** → `venv\Scripts\python.exe` таңдаңыз.
4. **Terminal → New Terminal** ашыңыз.
5. Жобаны іске қосу үшін README-дегі екі терминал командасын пайдаланыңыз.

ИИ чатына қолдануға арналған промпт:

> Мен Python тілінде «Қоймадағы тауарларды есепке алу» ақпараттық жүйесін жасап жатырмын. FastAPI қолданбасының бастапқы құрылымын құруға көмектес. Дерекқор модельдеріне, API маршруттарына және Streamlit интерфейсіне арналған папкалар болсын. Category, Supplier және Product кестелерін қолдан. Product кестесі category_id және supplier_id сыртқы кілттері арқылы байланыссын. requirements.txt файлына fastapi, uvicorn, sqlmodel, streamlit және requests енгіз. Әр файлдың міндетін қазақша түсіндір.

Осы жобаның коды Codex ИИ көмегімен дайындалды. Cursor немесе VS Code ішіндегі ИИ-чатты қолданғаныңызды көрсету қажет болса, промптті сол ортада орындап, жауабын оқып, өзіңіз түсінген соң ғана өзгерістерді қолданыңыз. Скриншоттарды нақты орындалған әрекеттерден алыңыз.

## 6 Виртуалды орта

Виртуалды орта әр жобаның кітапханаларын бөлек ұстайды. Бір жобадағы кітапхананы жаңарту басқа жобаның ортасын өзгертпейді.

Осы компьютерде дайын `venv` қолданылады. Жаңа компьютерде Python орнатылған соң:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

PowerShell активацияны бұғаттаса, саясатты өзгертпей-ақ `.\venv\Scripts\python.exe` деп тікелей іске қосуға болады. Мысалы:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Осы компьютердің `python` командасы Windows қолданба бүркеншік атына бағытталған. Сондықтан дайын ортаны тікелей шақырыңыз. `venv` басқа компьютерге көшірілмейді: сол жерде қайта жасалады.

## 7 GitHub репозиторийі

Git файл өзгерістерінің тарихын жергілікті компьютерде сақтайды. GitHub осы репозиторийдің интернеттегі көшірмесін сақтап, сілтеме арқылы көрсетуге мүмкіндік береді.

Жоба репозиторийі: https://github.com/nursayaya1/applied-is-project-2026. Төменде тапсырмадағы алғашқы жариялау тәртібі түсіндірілген; репозиторий дайын болса, оны қайта жасамаңыз.

1. GitHub аккаунтыңызбен кіріңіз, **New repository** таңдаңыз.
2. Атауын `applied-is-project-2026` деп жазыңыз, **Public** таңдаңыз.
3. **Add a README file** және **Add .gitignore → Python** таңдаңыз.
4. Репозиторий жасаңыз, **Code → HTTPS** сілтемесін көшіріңіз.
5. VS Code терминалында дайын жоба папкасынан бөлек жерге клондаңыз. Сіздің аккаунтыңызға арналған команда:

```powershell
cd ..
git clone https://github.com/nursayaya1/applied-is-project-2026.git
cd applied-is-project-2026
```

6. Дайын жобадан `app`, `frontend`, `docs`, `scripts`, `tests`, `.vscode`, `README.md`, `.gitignore` және үш `requirements` файлын клондалған папкаға көшіріңіз. README мен .gitignore файлдарын осы нұсқалармен ауыстырыңыз. `.git`, `venv`, `.tmp`, `.uv-cache`, `__pycache__` және `warehouse.db` көшірмеңіз. Клондалған папканың өз `.git` папкасы қалуы тиіс.
7. Өзгерістерді жіберіңіз:

```powershell
git status
git add .
git commit -m "feat: initial project structure with AI assist"
git push origin main
```

Браузерде кіру сұралса, өз аккаунтыңызбен кіріңіз. Құпиясөз не токенді кодқа немесе чатқа жазбаңыз. Егер Git авторын сұраса, өз атыңыз бен GitHub-тағы email-ді `git config user.name` және `git config user.email` арқылы орнатыңыз.

Клондау тәсілі README-і бар қашықтағы репозиторийдің тарихын сақтайды. Жергілікті бөлек тарихты күшпен жіберудің қажеті жоқ.

`git add .` өзгерістерді келесі сақтау нүктесіне дайындайды; `git commit` сақтау нүктесін жасайды; `git push` оны GitHub-қа жібереді. `main` — негізгі тармақтың атауы.

Соңында GitHub бетін жаңартып, файлдар мен README ішіндегі суретті тексеріңіз. `venv` интернетке шықпауы тиіс.

## 8 Оқытушыға көрсету

1. GitHub-та Public репозиторий сілтемесін ашыңыз.
2. README мен ER-диаграмманы көрсетіп, екі байланысты түсіндіріңіз.
3. `.gitignore` ішіндегі `venv/` жолын көрсетіңіз.
4. VS Code немесе Cursor-да жобаны, таңдалған Python ортасын және ИИ-чатты көрсетіңіз.
5. API мен Streamlit-ті екі терминалда іске қосыңыз.
6. Санат, жеткізуші, содан соң тауар қосыңыз.
7. `http://127.0.0.1:8000/docs` бетіндегі GET `/api/products` нәтижесін көрсетіңіз.

Скриншоттар: ER-диаграмма, GitHub файлдар тізімі, IDE құрылымы мен ИИ-чат, жұмыс істеп тұрған интерфейс. Тапсыруға өзіңіздің аты-жөніңізді және тобыңызды оқу орны талап еткен пішімде қосыңыз.

## 9 Қорғауға арналған жауаптар

**Неге үш кесте бар?** Санат, жеткізуші және тауар — бөлек нысандар; оларды бөлу қайталануды азайтады.

**Неге FastAPI мен Streamlit бөлек?** FastAPI мәліметпен жұмыс істейді, Streamlit пайдаланушы интерфейсін көрсетеді. Сол API-ді кейін басқа интерфейс те пайдалана алады.

**Деректер қайда сақталады?** Жоба түбіріндегі SQLite `warehouse.db` файлында. Сервер қайта іске қосылса да деректер қалады.

**Неге venv GitHub-қа салынбайды?** Ол көлемді және компьютерге тәуелді. Басқа компьютерде requirements арқылы қайта құрылады.

**Санат жоқ болса не болады?** API HTTP 404 қайтарады, тауар сақталмайды.

**Теріс баға жіберілсе не болады?** Енгізу схемасы оны қабылдамайды, HTTP 422 қайтады.

**Жоба не істей алмайды?** Бұл бастапқы нұсқада өңдеу, жою, пайдаланушыларға кіру және кіріс/шығыс журналдары жоқ.

Қысқа таныстыру мәтіні:

> Менің жобам — қоймадағы тауарларды есепке алу ақпараттық жүйесі. Дерекқорда Category, Supplier және Product деген үш кесте бар. Санат пен жеткізуші тауарлармен бірден көпке байланысады. Сервер FastAPI арқылы, дерекқор SQLModel және SQLite арқылы, интерфейс Streamlit арқылы жасалған. Python кітапханалары виртуалды ортада сақталады. .gitignore виртуалды орта мен жергілікті дерекқордың репозиторийге түсуіне жол бермейді.

## 11 Тексеру нәтижелері

2026 жылғы 3 қарашада Python 3.12 ортасында бес API тесті сәтті өтті. API серверінің іске қосылуы, Swagger беті, Streamlit интерфейсінің орындалуы және оның health жауабы тексерілді. `pip check` тәуелділіктер қайшылығын таппады. Тексерілген нұсқалар `requirements-lock.txt` ішінде сақталған.
