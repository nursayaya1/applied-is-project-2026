# Ветеринарлық клиника жобасын түсіндіру

№2–4 жалғасы: [ORM және seed](LAB_02_KK.md), [GET/POST және Swagger](LAB_03_KK.md), [PATCH/DELETE және сүзу](LAB_04_KK.md).

## 1 Тақырып пен мақсат

Тақырып: **Ветеринарлық клиникадағы қабылдауларды есепке алу ақпараттық жүйесі**.

Орысша: **Информационная система учёта приёмов в ветеринарной клинике**.

Жүйе жануар иелерін, жануарларды, ветеринарларды және қабылдауларды бір жерде сақтайды. Мысалы, Айгүл өзінің Марғау атты мысығын Дана есімді ветеринарға жоспарлы тексеруге жазады.

Зертханалық жұмыстың мақсаты — ақпараттық жүйенің архитектурасын жобалау, ER-диаграмма құру, Python виртуалды ортасын баптау, ИИ көмегімен құрылым жасау және Git тарихын жүргізу.

## 2 Төрт негізгі нысан

| Нысан | Өрістер | Міндеті |
|---|---|---|
| Owner — Иесі | id, name, phone | Жануар иесінің аты-жөні мен телефоны |
| Pet — Жануар | id, name, species, age_years, owner_id | Жануардың аты, түрі, толық жасы, иесі |
| Veterinarian — Ветеринар | id, name, specialty | Ветеринардың аты-жөні мен мамандануы |
| Appointment — Қабылдау | id, pet_id, veterinarian_id, starts_at, reason | Қай жануар, қай дәрігерге, қашан, не себепті келеді |

**PK — бастапқы кілт.** Әр жолдың бірегей нөмірі, біздің модельде `id`. Екі жануардың аты Марғау болса да, олардың ID нөмірлері бөлек болады.

**FK — сыртқы кілт.** Басқа кестедегі жазбаға сілтейді. `Pet.owner_id = 1` болса, жануар `Owner.id = 1` иесіне тиесілі.

Байланыстар:

- Owner → Pet: бір иеде бірнеше жануар болуы мүмкін.
- Pet → Appointment: бір жануар бірнеше рет қабылдауға келеді.
- Veterinarian → Appointment: бір ветеринар бірнеше қабылдау өткізеді.

Сызбадағы `1 : 0..N` бір жазбаның нөл немесе бірнеше байланысты жазбасы болатынын көрсетеді. Мысалы, жаңа ветеринар тіркелгенімен, оның қабылдаулары әлі болмауы мүмкін.

Қабылдауда иесінің аты-жөні қайта сақталмайды: оны жануар арқылы табамыз. Бұл мәліметтің қайталануын азайтады.

Сызба: `docs/er-diagram.png`. Өңделетін файл: `docs/er-diagram.drawio`. Оны draw.io сайтында **File → Open from → Device** арқылы ашыңыз.

## 3 Жүйенің жұмыс реті

1. Қолданушы Streamlit формасына мәлімет енгізеді.
2. Интерфейс FastAPI-ге HTTP сұранысын жібереді.
3. API енгізілген мәліметтерді тексереді.
4. SQLModel дерекқорға жазады.
5. API нәтижені JSON түрінде қайтарады.
6. Streamlit тізімді жаңартады.

**GET** — мәлімет оқу. **POST** — жаңа жазба қосу. **API** — интерфейс пен сервердің байланысу ережелері. **JSON** — мәлімет алмасудың мәтіндік пішімі.

## 4 Файлдар және кітапханалар

| Файл | Не істейді |
|---|---|
| app/main.py | FastAPI қолданбасын жасайды, маршруттарды қосады, іске қосылғанда кестелерді жасайды. |
| app/models/clinic.py | Төрт кестені және енгізілетін мәліметтердің схемаларын анықтайды. |
| app/api/routes.py | Тіркеу мен тізімді алу командаларын орындайды. |
| app/db/session.py | SQLite қосылымын және дерекқор сессиясын басқарады. |
| frontend/app.py | Қазақша беттерді, формаларды және кестелерді көрсетеді. |
| tests/test_api.py | Байланыстарды, енгізуді және уақыт қайшылығын тексереді. |
| tests/test_ui.py | Мәліметтер бар кезде интерфейстің дұрыс орындалуын тексереді. |
| requirements.txt | Қажет кітапханалар мен нұсқа аралықтары. |
| requirements-lock.txt | Ортада орнатылған нақты нұсқалар. |
| .gitignore | Виртуалды орта, дерекқор, кэш пен құпия файлдарды Git-тен шығарады. |
| README.md | Репозиторийдегі негізгі сипаттама мен іске қосу нұсқауы. |

FastAPI — API жасауға, Uvicorn — серверді іске қосуға, SQLModel — дерекқормен жұмыс істеуге, Streamlit — интерфейс жасауға, requests — HTTP сұраныстарына қажет.

`venv` әр жобаның кітапханаларын бөлек ұстайды. Оны GitHub-қа салмаймыз: жаңа компьютерде requirements арқылы қайта құрамыз.

## 5 Осы компьютерде ашу және іске қосу

1. VS Code ашыңыз.
2. **File → Open Folder** арқылы `C:\Users\Asus\Documents\ChatGPT\прикладное` папкасын таңдаңыз.
3. **Terminal → New Terminal** ашыңыз.
4. Алдыңғы сервер жұмыс істеп тұрса, **Ctrl+C** басыңыз.
5. Бірінші терминалда:

```powershell
.\venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

6. Терминалдағы **+** арқылы екінші терминал ашыңыз:

```powershell
.\venv\Scripts\python.exe -m streamlit run frontend/app.py
```

7. Браузерде http://localhost:8501 ашыңыз. Бұрынғы бет қалса, жаңартыңыз.
8. Екі терминалды жұмыс істеп тұрған күйінде қалдырыңыз. Тоқтату — әр терминалда **Ctrl+C**.

Осы компьютерде виртуалды орта дайын; кітапханаларды қайта орнату қажет емес. Деректер `vet_clinic.db` ішінде сақталады. Бұрынғы тақырыптың жергілікті дерекқоры жаңа қолданбаға пайдаланылмайды.

## 6 Демо мәлімет енгізу

1. **Иелері** бөлімі: Айгүл, `+7 700 000 00 00` деген оқу телефоны → **Иесін қосу**.
2. **Жануарлар**: Марғау, Мысық, 2 жас, Айгүл → **Жануар қосу**.
3. **Ветеринарлар**: Дана, Жалпы практика → **Ветеринар қосу**.
4. **Қабылдаулар**: Марғау, Дана, өзіңіз таңдаған күн, 10:00, Жоспарлы тексеру → **Қабылдауға жазу**.
5. Тізімде қабылдау пайда болады. База бос болғанда төрт көрсеткіш те 1 болады. Seed орындалған болса, демо жазбалар да есепке кіреді.
6. Сол ветеринарды немесе жануарды дәл сол күн мен уақытқа тағы жазып көріңіз: жүйе қайталауды қабылдамайды.

Күн мен уақыт Asia/Qyzylorda жергілікті уақыты бойынша енгізіледі. API минут дәлдігін күтеді: `2026-11-10T10:00:00`. Жануардың жасы бүтін сан, бір жасқа толмаса — 0.

## 7 API-ді көрсету

http://127.0.0.1:8000/docs ашыңыз. **GET /api/appointments → Try it out → Execute** басыңыз. Қабылдау JSON түрінде көрсетіледі.

| Код | Мағынасы |
|---|---|
| 200 | Тізім сәтті алынды |
| 201 | Жаңа жазба сақталды |
| 404 | Иесі, жануар немесе ветеринар табылмады |
| 409 | Жануар не ветеринар дәл осы уақытқа бұрын жазылған |
| 422 | Енгізілген өрістер қате немесе бос |

Иесі жоқ жануар тіркелмейді. Жануар не ветеринар жоқ қабылдау тіркелмейді. Теріс жас, бос атау және бос келу себебі қабылданбайды.

## 8 ИИ ортасы және промпт

VS Code-та Microsoft Python және GitHub Copilot бар. Copilot-қа өз GitHub аккаунтыңызбен кіріңіз. **Ctrl+Shift+P → Python: Select Interpreter** арқылы `venv\Scripts\python.exe` таңдаңыз. Cursor қолдануға да болады.

ИИ чатына арналған промпт:

> Мен Python тілінде «Ветеринарлық клиникадағы қабылдауларды есепке алу» ақпараттық жүйесін жасап жатырмын. FastAPI үшін бастапқы жоба құрылымын жаса. Дерекқор модельдері, API маршруттары және Streamlit интерфейсі бөлек папкаларда болсын. Owner, Pet, Veterinarian және Appointment деген төрт кесте құр. Pet.owner_id иесіне, Appointment.pet_id жануарға, Appointment.veterinarian_id ветеринарға сілтесін. requirements.txt файлына fastapi, uvicorn, sqlmodel, streamlit, requests кітапханаларын қос. Әр файлдың міндетін қазақша түсіндір.

Код Codex көмегімен дайындалған. IDE ішіндегі ИИ-чатты көрсету керек болса, промптті сол жерде орындап, ұсынылған өзгерістерді түсініп барып қолданыңыз.

## 9 Git және GitHub

Репозиторий: https://github.com/nursayaya1/applied-is-project-2026.

Git — өзгерістер тарихын сақтайды. GitHub — сол тарих пен файлдардың интернеттегі көшірмесі. Репозиторий атауы зертхана талабына сай сақталған; оның мазмұны ветеринарлық клиникаға арналған.

Жобаны басқа компьютерге алу:

```powershell
git clone https://github.com/nursayaya1/applied-is-project-2026.git
cd applied-is-project-2026
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Кейін өз өзгерістеріңізді жіберу:

```powershell
git status
git add .
git commit -m "feat: update veterinary clinic project"
git push origin main
```

`add` — commit-ке дайындайды, `commit` — сақтау нүктесін жасайды, `push` — GitHub-қа жібереді. `main` — негізгі тармақ. `venv` пен `*.db` `.gitignore` арқылы жіберілмейді.

## 10 Қорғауға дайындық

Қысқа таныстыру:

> Менің тақырыбым — ветеринарлық клиникадағы қабылдауларды есепке алу ақпараттық жүйесі. Төрт кесте бар: иелер, жануарлар, ветеринарлар және қабылдаулар. Бір иеде бірнеше жануар, бір жануарда бірнеше қабылдау болады. Әр қабылдау нақты ветеринарға байланысты. Интерфейс Streamlit арқылы, API FastAPI арқылы жасалған. Деректер SQLModel көмегімен SQLite базасына сақталады. Жоба GitHub-та, виртуалды орта мен жергілікті дерекқор репозиторийге жіберілмейді.

**Неге төрт кесте?** Әр нысанның мәліметін бөлек сақтап, олардың арасында сыртқы кілт арқылы байланыс жасаймыз.

**Неге FastAPI мен Streamlit бөлек?** FastAPI мәліметтерді өңдейді; Streamlit пайдаланушыға форма мен нәтижені көрсетеді.

**Деректер қайта ашқанда қала ма?** Иә, SQLite файлында сақталады.

**Бір уақытта екі қабылдау бола ма?** Әртүрлі ветеринарлар әртүрлі жануарларды бір уақытта қабылдай алады. Бір ветеринар немесе бір жануар дәл сол уақытқа қайталап жазылмайды.

**Жүйенің шектеуі қандай?** Бұл оқу жобасының API бөлігінде өңдеу, жою және сүзу бар; олар Swagger арқылы орындалады. Авторизация, төлемдер және емдеу картасы жоқ. Қабылдау ұзақтығы есептелмейді; тек басталу уақытының дәл қайталануы тексеріледі.
