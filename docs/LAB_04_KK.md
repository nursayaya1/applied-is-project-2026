# Зертханалық жұмыс 4 — PATCH, DELETE және сүзу

Барлық төрт нысан үшін толық CRUD бар. Маршруттар `app/api/routes.py`, Update схемалары `app/models/clinic.py` ішінде.

## PATCH

Мысалы, PATCH `/api/pets/{record_id}` денесіне тек мынаны беріңіз:

```json
{"age_years":4}
```

`model_dump(exclude_unset=True)` тек клиент нақты жіберген өрістерді алады. `sqlmodel_update(values)` соларды өзгертеді. Аты, түрі және иесі өзгермейді. Жазба жоқ болса 404. Теріс жас, бос атау, артық `id` немесе `null` — 422.

Update схемасының барлық өрісі Optional және default=None. **Өрісті жібермеу** — ескі мәнін сақтау. **Өрісті null деп жіберу** — оны босату талабы; біздің міндетті бағандар бұған жол бермейтіндіктен 422 қайтарылады. Бос `{}` — ештеңе өзгертпейтін жарамды PATCH.

Жануардың иесін немесе қабылдаудың жануарын/ветеринарын ауыстырғанда жаңа ID бар екені тексеріледі. Қабылдаудың уақытын ауыстырғанда дәл сол уақыттың бос екені база шектеуімен қорғалады. Қайшылық болса 409 және rollback: бұрынғы дерек сақталады.

## DELETE

DELETE `/api/appointments/{record_id}` қабылдауды физикалық жояды. Жауап — **204, бос дене**. 204 жауапта JSON хабарламасы болмайды. Кейін GET, PATCH немесе DELETE сол ID-ге жасалса — 404.

Қауіпсіздік ережесі: иесінің жануарлары болса, жануардың не ветеринардың қабылдаулары болса, DELETE 409 қайтарады. Алдымен байланысты қабылдауды, содан соң жануарды, одан кейін иесін жою керек. Жою кезінде деректер автоматты каскадпен жоғалмайды.

## Сүзгілер

| Тізім | Query параметрлері |
|---|---|
| `/api/owners` | `search` — аты-жөнінің бөлігі |
| `/api/pets` | `search`, `species`, `owner_id`, `min_age`, `max_age` |
| `/api/veterinarians` | `search`, `specialty` |
| `/api/appointments` | `search` — келу себебі, `pet_id`, `veterinarian_id`, `starts_from`, `starts_until` |

Баға біздің модельде жоқ, сондықтан тапсырмадағы min_price/max_price орнына жануардың min_age/max_age аралығы қолданылды. Төменгі және жоғарғы шекаралар нәтижеге кіреді. Минимум максимумнан үлкен болса — 422. Нәтиже жоқ болса — бос `[]`, 404 емес.

Мысалдар:

```text
/api/pets?search=марға&min_age=1&max_age=5
/api/pets?species=мысық
/api/appointments?starts_from=2026-11-10T00:00:00&starts_until=2026-11-12T23:59:00
```

Іздеу Unicode casefold арқылы қазақша үлкен/кіші әріптерді теңестіреді. Мысалы, `МАРҒА` және `марға` бірдей нәтиже береді. `%` және `_` кәдімгі таңба ретінде қаралады. SQLModel select/where параметрленген сұраныс жасайды; пайдаланушы мәтіні SQL командасына тікелей жалғанбайды.

## Swagger сценарийі

1. Серверді іске қосып, http://127.0.0.1:8000/docs ашыңыз.
2. GET `/api/pets` → Try it out → `search=марға`, `min_age=1`, `max_age=5` → Execute.
3. Өзге деректерді қозғамау үшін POST `/api/owners` арқылы `{"name":"CRUD сынақ","phone":"DEMO-TEST"}` қосыңыз. Жауаптағы ID-ді көшіріңіз.
4. PATCH `/api/owners/{record_id}` арқылы `{"phone":"DEMO-UPDATED"}` жіберіңіз. 200 келуі тиіс.
5. GET арқылы тек телефонның өзгергенін тексеріңіз.
6. DELETE арқылы жаңа сынақ иесін жойыңыз. Оның жануарлары болмағандықтан 204 келеді.
7. Сол ID-ге PATCH жіберіңіз — 404.
8. Қосымша: бар жануарға `{"age_years":-2}` жіберіңіз — 422; бұрынғы мәні сақталады.

Жұмыс істеп тұрған Streamlit интерфейсі тіркеу мен тізімдеуді көрсетеді. №3–4 зертханалардың толық API мүмкіндіктерін Swagger арқылы көрсетіңіз.

## ИИ промпті және қорғау

> Ветеринарлық клиниканың төрт нысанына Update схемалары, PATCH, DELETE және query сүзгілерін тексер. PATCH exclude_unset қолдансын. Байланысты жазбаларды жою 409 қайтарсын. Қате ID — 404, қате өріс — 422. Іздеу параметрленген SQL арқылы орындалсын.

CRUD: Create — POST, Read — GET, Update — PATCH, Delete — DELETE. PATCH толық объектіні емес, көрсетілген өрістерді ғана өзгертеді. ID табылмаса, require_record функциясы HTTPException(404) тастайды; әрі қарай update/delete орындалмайды.

Ресми негіз: [SQLModel жаңарту үлгісі](https://sqlmodel.tiangolo.com/tutorial/fastapi/update/).
