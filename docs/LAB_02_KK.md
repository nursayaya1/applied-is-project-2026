# Зертханалық жұмыс 2 — ORM және дерекқор

Тақырып: ветеринарлық клиника. Модельдер `app/models/clinic.py`, қосылым `app/db/session.py`, деректерді толтыру `app/db/seed.py` ішінде. Тапсырмадағы models.py және db.py міндетін осы файлдар атқарады. Дерекқор атауы — `vet_clinic.db`.

## Байланыстар

`Owner.pets ↔ Pet.owner`, `Pet.appointments ↔ Appointment.pet`, `Veterinarian.appointments ↔ Appointment.veterinarian` — `Relationship(back_populates=...)` арқылы жасалған бірден көпке байланыстар.

`Pet.veterinarians ↔ Veterinarian.patients` — Appointment аралық кестесі арқылы көптен көпке байланыс. Қабылдау сол байланыстың күнін және себебін де сақтайды. Бұл екі тізім `viewonly=True`: оларды оқу үшін қолданамыз, байланысты өзгерту үшін қабылдау жасаймыз не жоямыз. Бір жануар бір ветеринарға бірнеше рет келуі мүмкін; ветеринарлар тізімінде ол бір рет көрсетіледі.

`foreign_key` дерекқордағы тұтастықты қорғайды; `Relationship` Python объектілері арқылы байланысқан мәліметті алуға мүмкіндік береді. Мысалы, ашық Session ішінде `pet.owner.name` жануар иесінің атын береді.

## Орындау

Жоба түбірінде:

```powershell
.\venv\Scripts\python.exe seed.py
```

Бос базаға 3 ие, 3 жануар, 3 ветеринар және 4 қабылдау қосылады. Атаулар интерфейсте қосымша белгілерсіз көрсетіледі; телефондар — оқу мысалдары. Бұрынғы seed нұсқасының «(демо)» белгілері автоматты тазаланады. SQL логтары қосулы: жаңа база үшін CREATE TABLE, жаңа жазбалар үшін INSERT көрінеді. Бұрын кестелер бар болса, CREATE TABLE қайта орындалмайды.

Қайта іске қосу жазбаларды көбейтпейді және пайдаланушының деректерін өшірмейді. Нәтижеде тек жаңадан қосылған жолдардың саны көрсетіледі. Дәл сол қабылдау уақытын бұрынғы жазба алып қойса, seed оны өткізіп жібереді.

```powershell
.\venv\Scripts\python.exe -m pytest tests/test_database.py -q
git check-ignore vet_clinic.db
```

`init_db()` кестелерді жасайды. `Session` транзакция ішінде жазбаларды сақтайды. `commit()` өзгерістерді бекітеді. `create_all()` бұрынғы кестелердің құрылымын өзгертетін миграция құралы емес.

## ИИ промпті және қорғау

> SQLModel жобамда Owner, Pet, Veterinarian, Appointment кестелері бар. Foreign key және екіжақты Relationship байланыстарын тексер. Appointment арқылы Pet пен Veterinarian арасындағы көптен көпке байланысты түсіндір. Бұрынғы деректерді өшірмейтін, қайталап іске қосуға болатын seed скриптін тексер.

Python моделі — өрістерді, типтерді, валидацияны және байланыстарды сипаттайтын класс. Реляциялық кесте — дерекқордағы бағандар мен сақталған жолдар. ORM модель объектісін кесте жолына сәйкестендіреді. Модель коды өзгерген сайын бұрынғы кесте автоматты өзгермейді.

Оқытушыға: модель кодын, `Relationship`, seed орындалуын, SQL логтарын және `.gitignore` ішіндегі `*.db` ережесін көрсетіңіз.

Ресми негіз: [SQLModel back_populates](https://sqlmodel.tiangolo.com/tutorial/relationship-attributes/back-populates/), [қосымша өрістері бар байланыс моделі](https://sqlmodel.tiangolo.com/tutorial/many-to-many/link-with-extra-fields/).
