# Зертханалық жұмыс 7 — Тесттер және жобаны қорғау

## Не істеу керек болды?

GET және POST үшін кемінде 2–3 автоматты тест жазу; pytest арқылы тексеру; кодты қателерге қарап шығу; README-ді автор, пәндік сала, ER-схема, технология, іске қосу және тест бөлімдерімен рәсімдеу; Docker-дегі жүйені көрсету.

## Біздің жобада қалай жасалды?

requirements.txt ішінде pytest және httpx бар. tests/conftest.py әр тестке бөлек SQLite жад базасын құрып, Depends(get_session) тәуелділігін тест сессиясына ауыстырады. Соңында override тазаланады және engine жабылады. Бұл пайдаланушының жұмыс базасын сақтайды.

| Файл | Не тексеріледі? |
|---|---|
| tests/test_api.py | GET 200, POST 201, PATCH, DELETE, 404, 409, 422, сүзу және сыртқы кілттер |
| tests/test_database.py | Seed қайталанғанда артық дерек қоспауы және ORM байланыстары |
| tests/test_ui.py | Қосу → іздеу → растау → жою; байланысты иені жоюға тыйым; сервердің қолжетімсіздігі |
| scripts/smoke_check.py | Нақты Uvicorn, Swagger, Streamlit серверлері және беттің рендері |

2026-11-11: **35 тест өтті**. Бір сыртқы TestClient/httpx deprecation ескертуі бар; ол тесттің қатесі емес. Контейнерлердің орындалу күйін №6 құжатынан қараңыз.

## Код аудиті

- SQL сұрауларында select, where, ORM параметрлері қолданылады; қолданушы мәтіні SQL-ге конкатенацияланбайды.
- Create схемалары клиент берген id сияқты артық өрістерді қабылдамайды; бос ат, теріс жас, жарамсыз уақыт 422 қайтарады.
- SQLite foreign_keys қосылған. Байланысы бар иені/жануарды/дәрігерді жою 409 қайтарады.
- Қабылдау уақытының қайталануы API-де де, дерекқордың unique шектеулерінде де қорғалған. IntegrityError кезінде rollback және 409 бар.
- PATCH тек берілген өрістерді жаңартады; жоқ ID — 404. Қате өзгерістен кейін бастапқы жазба сақталатыны тексеріледі.
- UI-дегі DELETE 204 жауабы JSON ретінде талданбайды. HTML қатесі, желі қатесі және JSON емес жауап бетте түсінікті хабармен көрсетіледі.
- POST/DELETE сәтті хабарлары rerun кезінде жоғалмайды. Жою алдында нақты растау қажет.
- Docker порттары host-та тек 127.0.0.1-ге байланған; база volume-да, құпиялар мен venv build context-тен шығарылған.

Шектеулер: пайдаланушы авторизациясы жоқ; интернетке жариялауға дайын сервис емес. Уақыт бойынша толық аралықтың қабаттасуы емес, басталу уақытының дәл бірдей болуы тексеріледі.

## Қалай ашып тексеремін?

1. VS Code-та жоба папкасын ашыңыз → Terminal → New Terminal.
2. `.\venv\Scripts\python.exe -m pytest -q` орындаңыз. Соңғы жолда `35 passed` болуы тиіс.
3. tests/test_api.py ашып, test_clinic_flow көрсетіңіз: POST арқылы жазбалар жасалып, GET арқылы қайта оқылады, кодтар assert арқылы тексеріледі.
4. tests/conftest.py ашып, тест базасы мен dependency override көрсетіңіз.
5. README-ден өз аты-жөніңізді, ER-схеманы және іске қосу командаларын көрсетіңіз.

## Docker-де қорытынды көрсету

Docker Desktop іске қосылып, `docker version` Server бөлігін көрсеткен соң:

```powershell
docker compose down
docker compose up --build -d
docker compose ps
docker compose exec backend python seed.py
```

1. http://localhost:8501 ашыңыз.
2. «Иелер» бөлімінде жаңа сынақ ат пен телефон енгізіп, қосу батырмасын басыңыз.
3. Іздеу жолына жаңа аттың бөлігін енгізіп Enter басыңыз — тек сәйкес жазбалар қалуы тиіс.
4. «Жазбаны жою» бөлімін ашыңыз, жаңа жазбаны таңдаңыз, растау белгісін қойып жойыңыз.
5. http://localhost:8000/docs ашып, GET /api/owners → Try it out → Execute басыңыз.
6. Терминалда pytest нәтижесін және `git log --oneline` тарихын көрсетіңіз.

down деректер volume-ын сақтайды; down -v қажет емес. Жеті аптаға жалған коммит жасалмайды — Git нақты орындалған жұмыстарды көрсетеді.

## Қорғауда айтуға болатын түсіндірме

«№5 жұмыста Streamlit интерфейсін API-ге Requests арқылы қостым. Қосу формалары, серверлік іздеу және растаумен жою бар. №6 жұмыста backend пен frontend үшін бөлек Dockerfile және ортақ Compose дайындадым; база volume-да сақталады. №7 жұмыста 35 автоматты тестті өткіздім: олар API-ді, ORM байланыстарын және пайдаланушы әрекеттерін тексереді. README-де жүйенің құрылымы мен іске қосылуы түсіндірілген».

Docker-ді нақты іске қосып тексергеннен кейін ғана «контейнерлер жұмыс істеді» деп айтыңыз.

**Тест не үшін керек?** Код өзгергенде бұрынғы функциялардың бұзылмағанын автоматты анықтайды.

**assert деген не?** Күтілетін нәтиже орындалмаса тестті тоқтататын тексеру.

**TestClient не істейді?** FastAPI-ге HTTP сұрауын тест ішінде жібереді; бөлек Uvicorn қажет емес.

**Mock пен интеграциялық тест айырмасы?** Mock сыртқы жауапты алмастырады. Интеграциялық тест бірнеше компоненттің бірге жұмысын тексереді; UI тесттерінде Requests нақты TestClient пен оқшауланған базаға бағытталады.

**Неге жеке база?** Тесттер нақты қолданушы жазбаларын өзгертпеуі үшін.
