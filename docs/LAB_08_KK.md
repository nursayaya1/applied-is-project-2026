## 1 Не қосылды

- Кіру, шығу, мерзімі 8 сағаттық және қайтарылатын bearer сессиясы.
- Admin — оқу/қосу/өңдеу/жою; viewer — тек оқу. Рөл серверде тексеріледі.
- Құпиясөз PBKDF2-HMAC-SHA256, кездейсоқ salt және 600 000 итерациямен сақталады. Базада ашық құпиясөз немесе bearer токен жоқ; токеннің SHA256 хэші ғана бар.
- PUT төрт нысанға толық өрістерді талап етеді; бұрынғы PATCH тек көрсетілген өрістерді өзгертеді.
- Жарамсыз JSON — 400, жоқ ID — 404, кірусіз сұраныс — 401, рөл жетпесе — 403, өріс қатесі — 422, байланыс/уақыт қайшылығы — 409.
- 57 автоматты тест, 14 нақты HTTP тексерісі, Locust және Bandit, GitHub Actions.

## 2 Қалай ашамын

VS Code → File → Open Folder → жоба папкасы. Terminal → New Terminal.

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements-quality.txt
.\venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Екінші терминал (+ батырмасы):

```powershell
.\venv\Scripts\python.exe -m streamlit run frontend/app.py
```

http://localhost:8501 ашыңыз. Логин **nursaya**; осы компьютерде дайындалған құпиясөз **.local/ACCESS.txt** файлында. VS Code Explorer → .local → ACCESS.txt. Оны жарияламаңыз және есеп скриншотына қоспаңыз. **reader** аккаунтының рөлі — тек оқу; оның құпиясөзі де сол файлда.

Басқа компьютерге репозиторийді клондалғанда аккаунт автоматты берілмейді. Әкімші жасау:

```powershell
.\venv\Scripts\python.exe -m scripts.create_user --username nursaya --role admin
```

Құпиясөзді екі рет енгізіңіз (терминалда таңбалар көрінбейді). Кемінде 12 таңба, үлкен және кіші латын әрпі, сан, арнайы таңба қажет. Viewer үшін username reader және role viewer пайдаланыңыз. Docker режимінде: `docker compose exec backend python -m scripts.create_user --username nursaya --role admin`.

## 3 Беттен нені басамын

1. Логин/құпиясөз → **Кіру**. Төрт бөлім ашылады.
2. **Иелері** → жаңа ат, телефон → **Иесін қосу**.
3. Іздеу өрісіне аттың бөлігін жазыңыз → Enter.
4. **Жазбаны жою** → өзіңіз қосқан сынақ жазбаны таңдаңыз → растау құсбелгісі → **Жою**.
5. Сол жақтан **Шығу** басыңыз. Бұрынғы сессия серверде жарамсыз болады.
6. reader аккаунтымен кіріңіз. Мәлімет көрінеді; қосу батырмалары өшірілген, жою көрсетілмейді. Серверге тікелей өзгерту сұранысы да 403 қайтарады.

## 4 Swagger арқылы қауіпсіздік пен PUT тексеру

1. http://localhost:8000/docs ашыңыз.
2. **POST /api/auth/login → Try it out**. username/password енгізіңіз → **Execute**.
3. Жауаптағы access_token мәнін ғана көшіріңіз. Оны ешкімге жібермеңіз.
4. Жоғарыдағы **Authorize** → Value өрісіне токенді қойыңыз → **Authorize → Close**. Bearer сөзін қолмен қоспаңыз.
5. GET /api/owners → Try it out → Execute: 200.
6. POST /api/owners арқылы жаңа сынақ иесін қосыңыз: 201. Жауаптағы id-ді есте сақтаңыз.
7. PUT /api/owners/{record_id}: сол id, жаңа name және phone → Execute: 200. Екі өріс те міндетті.
8. DELETE сол id: 204. GET сол id: 404.
9. Authorize → Logout → Close, қайта GET /api/owners: 401.

## 5 Тесттерді іске қосу


Күтілетін нәтиже: 57 passed; 14 HTTP checks; Bandit нәтижесіндегі results бос. TestClient/httpx туралы deprecation ескертуі тест қатесі емес.

Тесттер тест базаларын қолданады. `test_database_transaction_atomic_rollback` бір транзакцияға дұрыс Owner және name=None болатын қате Pet енгізеді. NOT NULL қатесінен кейін rollback жасалып, екеуі де базада қалмайтыны тексеріледі. Одан кейін дұрыс жазба сақталып, сессияның жұмысқа жарамды екені дәлелденеді.

## 6 Жүктемені тексеру

Сценарийлер: 5 пайдаланушы/60 секунд, 20/120, 50/180, 100/180. Барлығы шамамен 9 минут және іске қосу уақыты. Сынақ тек уақытша база мен localhost:18008 адресіне жүреді. Нақты нәтижелер **docs/reports/lab08/load/** ішінде: summary.json, CSV, resources.csv және HTML есептері. Әр сценарийдің HTML файлын браузерде ашуға болады. CI-де тек 5 пайдаланушы/10 секундтық қысқа регрессиялық сынақ жүреді; ол толық 9 минуттық өлшеуді алмастырмайды.

## 7 GitHub Actions қай жерде

1. [Репозиторийді ашыңыз](https://github.com/nursayaya1/applied-is-project-2026).
2. Жоғарыдан **Actions** басыңыз.
3. Сол жақтан **Clinic quality** таңдаңыз.
4. Аяқталған жасыл іске қосуды ашыңыз.
5. **quality** job ішінде pytest, Bandit, HTTP және қысқа Locust қадамдарын ашып көрсетіңіз.
6. **docker** job ішінде екі контейнерді құрастыру және тексеру нәтижесі болады.
7. Беттің төменгі жағындағы **Artifacts → quality-reports** арқылы есептерді жүктеуге болады.

Әдейі қате сценарийі: **Run workflow** → demonstrate_failure құсбелгісі → Run workflow. Ол қолданба кодын өзгертпей, уақытша тестте `assert 200 == 201` орындатып CI-ді қызыл етеді. Қатені түзету мысалы: қайта Run workflow басып, құсбелгіні алып тастаңыз. Енді қалыпты тесттер өтеді. Бұл қате тек оқу тәжірибесі; default push тексерісі оны орындамайды.

CI автоматты тестілеу мен контейнер құрастыруды орындайды. Продакшнға автоматты жариялау жоқ.

## 8 Қысқа қорғау жауаптары

**Unit және Integration:** unit бір функцияны бөлек тексереді (құпиясөз саясаты); integration API, авторизация, ORM және базаның бірге жұмысын тексереді.

**Response time және throughput:** бір сұраныстың жауабына кеткен уақыт және секундына өңделген сұраныстар саны. p95 — сұраныстардың 95%-ы осы уақыттан тезірек аяқталатын шек.

**Транзакция:** бірнеше өзгерісті бірге бекіту; қате болса rollback арқылы кері қайтару.

**Қауіпсіздік:** 401 — кірмеген/жарамсыз сессия, 403 — кірген, бірақ рөлі жеткіліксіз. Құпиясөздер хэштеледі, SQL сұраулары параметрленеді, қателерде енгізілген құпия мәлімет қайталанбайды.

**Жүктеме өссе не істеуге болады:** алдымен өлшеу; кейін pagination, индекстер, PostgreSQL, қажет жерде кэш және бірнеше worker. SQLite жазу кезіндегі блоктауы ескеріледі. Бұл тесттен өндірістік максимал сыйымдылықты анықтауға болмайды.

**Тестілеудің шектеулері:** қамтылмаған жағдайлар, сыртқы жүйелер және желі әсері қалады. Bandit нөл ескертуі осалдық мүлде жоқ деген сөз емес. Бұл жобада HTTPS reverse proxy, парольді қалпына келтіру және кіру әрекеттерін rate limit жасау әлі жоқ; интернетке жарияламас бұрын олар қажет.

## 10 Жүктемеден табылған нақты ақаулар

Бастапқы QueuePool 5+10 қосылым шегінде 100 пайдаланушы кезек күтіп, TimeoutError алды. NullPool енгізілді. Қайта сынақта database is locked байқалды; SQLite WAL режимі қосылды. Бастапқы және аралық сәтсіз нәтижелер load-before/raw және load-nullpool папкаларында сақталды; соңғы нұсқаның өлшеулері load папкасында. Нақты салыстыру мен қорытынды REPORT_KK.md есебінде.
